# Website Build Brief

## Project Name

Petals & Pearls Foundation Website

## Project Purpose

Create a professional public-facing website for the Petals & Pearls Foundation. The website should explain the foundation’s purpose, communicate its mission, support donor confidence, highlight community impact, and provide a clear structure for future updates.

The website should be suitable for the general public, potential donors, community partners, foundation stakeholders, and members connected to the chapter.

## Primary Audience

The website should be designed for:

- General public visitors
- Donors and sponsors
- Community partners
- Foundation stakeholders
- Chapter members
- Individuals seeking information about programs, scholarships, events, or community initiatives

## Desired Tone

The tone should be:

- Professional
- Warm
- Trustworthy
- Community-focused
- Elegant
- Clear
- Easy for non-technical visitors to understand

The site should feel polished and credible, but not overly corporate or cold.

## Visual Style

The website should have a clean foundation-style design.

Preferred visual direction:

- Elegant and professional
- Easy to read
- Strong use of white space
- Warm community-focused imagery
- Clear calls to action
- Mobile-friendly layout
- Modern but not trendy
- Distinct from sister foundation websites

The design should avoid clutter, overly flashy animation, or anything that appears too generic.

## Required Pages

The website should include the following pages:

1. Home
2. About the Foundation
3. Programs / Initiatives
4. Scholarships or Community Impact
5. Events
6. Donate
7. Contact

## Required Homepage Sections

The homepage should include:

1. Header and navigation
2. Hero section with mission-oriented message
3. Foundation purpose or mission section
4. Programs or initiatives preview
5. Community impact section
6. Donation call-to-action
7. Events or news preview
8. Leadership or board preview section, if approved content is available
9. Contact/footer section

## Donation Requirements

The website should include visible donation calls-to-action.

Donation language should be clear and donor-friendly.

Do not include final tax-deductible language unless that wording is provided and approved by the foundation.

Use placeholders where final donation platform links or payment details are not yet available.

## Content Rules

Use approved content from the repository whenever available.

Use placeholder text only where final content is missing.

Placeholder text must be clearly marked so stakeholders know it needs review or replacement.

Do not invent facts.

## Codex Must Not Invent

Do not invent or assume:

- Board member names
- Officer names
- Scholarship amounts
- Donation tax language
- IRS status language
- Event dates
- Program names
- Community partnerships
- AKA authorization language
- Legal claims
- Financial claims
- Historical claims
- Contact information that has not been provided
- Photos or image permissions

If required information is missing, use a clear placeholder and list it as missing content.

Suggested files:

The first homepage should be easy for stakeholders to review in a browser.

## Build Priorities

Codex should prioritize:

1. Clear homepage structure
2. Professional first impression
3. Mobile responsiveness
4. Donor-friendly calls to action
5. Simple navigation
6. Easy stakeholder review
7. Clean code organization
8. Clearly labeled placeholders

## Review Expectations

After creating or revising the website, Codex should summarize:

1. What was created
2. Which files were changed
3. What content is still missing
4. Any assumptions made
5. Any recommended next steps
